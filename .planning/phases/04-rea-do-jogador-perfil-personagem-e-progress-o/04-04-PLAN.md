# 04-04: Aba de missões do jogador

<objective>
Implementar uma aba dedicada de missões em `/play`, exibindo missões disponíveis, ativas, concluídas, bloqueadas por nível e progresso do jogador com dados persistidos no Supabase, sem implementar conclusão automática, recompensas pós-combate ou lógica de combate.
</objective>

<context>
- Depende do shell player, dashboard, navegação, inventário e magias concluídos até `04-03`.
- Este plano existe para isolar a aba de missões como uma entrega própria após os demais blocos do player.
- Missões devem consumir `quests`, `quest_steps` e `character_quests`.
- Combate, vitória/derrota, recompensas finais e atualização pós-combate pertencem à Phase 5.
</context>

<tasks>

## T1 - Implementar serviço de missões do jogador

**Type:** code
**Files:** `src/services/playerQuests.js`
**Action:**
- Criar função para carregar catálogo de `quests`.
- Criar função para carregar `quest_steps` agrupados por `quest_id`.
- Criar função para carregar `character_quests` do perfil atual.
- Mesclar os dados em uma estrutura única por missão, com estado calculado:
  - `available` quando atende `min_level` e não há progresso ativo;
  - `active` quando existe `character_quests.status = 'active'`;
  - `completed` quando existe `character_quests.status = 'completed'`;
  - `failed` quando existir estado falho;
  - `locked` quando `profile.level < quests.min_level`.
- Manter todas as leituras sob RLS do usuário autenticado.

**Acceptance criteria:**
- Serviço retorna missões com título, descrição, nível mínimo, recompensas, etapas e estado.
- Missões sem progresso do jogador ainda aparecem como disponíveis ou bloqueadas.
- Falhas de Supabase retornam erro normalizado, sem quebrar o shell inteiro.

**Verify:**
- Testar com perfil nível 1.
- Alterar nível no Supabase Studio e validar mudança de `locked` para `available`.
- Conferir que apenas `character_quests` do próprio perfil é carregado.

## T2 - Criar UI da aba Missões

**Type:** code
**Files:** `src/player/questsView.js`, `src/player/player.css`
**Action:**
- Criar renderizador `questsView`.
- Exibir grupos ou filtros simples: Ativas, Disponíveis, Concluídas e Bloqueadas.
- Para cada missão, exibir:
  - título;
  - descrição curta;
  - estado;
  - nível mínimo;
  - progresso resumido;
  - recompensas compactas quando `quests.rewards` estiver disponível.
- Exibir etapas com leitura clara, sem transformar em tabela densa.
- Criar empty states para ausência de missões e ausência de progresso.

**Acceptance criteria:**
- Missões disponíveis e progresso aparecem com estado claro.
- Missões bloqueadas por nível não parecem erro.
- Recompensas aparecem como preview, não como concessão automática.
- A UI permanece legível em mobile e desktop.

**Verify:**
- Testar com dados seed.
- Testar sem `character_quests`.
- Testar missões bloqueadas por nível.
